============

Shared rules and procedure: ``../README.rst``.

Goal
----

Know where things are and where to click: tile, facing and current target of
every NPC; facing and target of the local player; and a projection from a
world tile to a physical screen pixel, without screenshots.

Read first
----------

* ``src/npcs.c``, ``src/position.c``, ``src/player_hits.c`` (actor layouts
  already mapped).
* ``include/rs3/rs3.h``: ``rs3_npc``, ``rs3_position``, ``rs3_minimap``,
  ``rs3_interact``.
* ``docs/research-notes.rst``.

Owns
----

* ``src/spatial.c``, ``src/spatial.h``, ``include/rs3/spatial.h``
* ``tests/native/test_spatial.c``
* ``docs/spatial.rst``, ``docs/validation/spatial-validation.json``
* Own registration lines in the shared wiring files.

Depends on
----------

S0a for the field names. S0b decides the profile; until it is done, work on the
original executable profile.

Delivers
--------

* ``WorldState.npcs[].tile``, ``.facing``, ``.target``.
* ``WorldState.player.facing``, ``.target``.
* A projection accessor: tile to screen pixel, with a validity flag when the
  tile is off screen or the camera state is unknown.

Done when
---------

Fixture tests pass, NPC tiles agree with observed movement live, and projected
pixels land on the entity for at least twenty checked samples across camera
angles. Record the results in the validation report.

Needs the user
--------------

One session: stand near several NPCs, walk around them, rotate and zoom the
camera, and attack one so target fields change.

The current native implementation reads poses and physical projected pixels
on the running original 951-3 executable. Before marking this track done:

1. Completed: the two manual encounters recorded changing player/NPC poses.
   The user then confirmed 22 Training dummy projections through 22 distinct
   camera orientations using the read-only marker. No game inputs were sent.
2. Combat-target identity is still unmapped. One selected-target label was
   captured; the older context+0x98 candidate did not match its runtime ID.
   A cleared-target label was not recorded. A fresh, explicitly labelled
   select/clear sequence is needed after finding another static candidate.
3. Repeat layout/signature verification on the Compatibility Mode executable
   before enabling P1 there. The running binary currently hashes to the original.

Requests
--------

The user authorized P1/P2 include and snapshot-storage registration in
``src/context.h`` on 2026-11-11. Those registration lines are included here.

No changes to another track's module are requested. Static layouts, limits,
the public ABI and pending validation are documented in ``docs/spatial.rst``
and ``docs/validation/spatial-validation.json``. Combat targets remain unknown;
``facingTarget`` is not a target-entity mapping.
