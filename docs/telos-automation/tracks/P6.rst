Goal
----

A measured table of every Telos attack: which animation sequence means which
attack, in which phase, with which damage style and components, how attacks are
counted between specials, and how long after the cue the prayer is checked.
Today only four sequences are labelled, all from 300% phase 1.

Delivers
--------

``profiles/telos_attacks.json``: per phase and enrage band, each sequence with
its attack name, style, required protection, hit components, the measured
cue-to-check window, a sample count and a ``validated`` flag. Rows from guides
are marked as leads and are never ``validated``.

Done when
---------

Phases 1-5 at 300% each have every observed sequence labelled or listed as
unlabelled, with sample counts, and tracks D1 and D2 can load the file. Higher
enrage bands are added later during track L.

Needs the user
--------------

Complete a manual 300% practice attempt reaching phase 5 while the recorder
runs. Use Ctrl+F1 Magic, Ctrl+F2 Ranged, Ctrl+F3 Soul Split and Ctrl+F4 Melee
manually. Report phase changes and each special by name; repeat missing phases
as needed. No automatic prayer input is enabled. Raw captures stay local.

The 2026-11-13 catalogue has 28 scoped rows from the two labelled phase-1
captures and the saved P2 manual captures. It lists observed sequences in
phases 1-4 at 300% and a separate 500% band. Phase 5 remains not captured.
Only four old phase-1 labels are classified; unlabelled sequences, hit
components and protection-check windows remain explicit unknowns.

The additional live 300% attempt on 2026-11-13 reached the second phase-4 font
according to the user. It retained 61 Telos cues and 13 manual prayer keys,
with zero action/player-hit event losses. This recorder has the packed stage
but not P2's active-encounter VARP guard or per-phase user timestamps. These
new cues are counted as unassigned, rather than claiming exact phase labels.

Consumer API: ``rs3_reader.telos_prayer.load_attack_catalogue()`` returns
immutable metadata. ``lookup(phase, enrage, sequence, executable_sha256=...,
context=..., require_validated=...)`` requires exact scope; unknown returns
None. The historical melee labels require context ``isolated_p1_melee``.
D1 may use classification labels; D2 must require validated timing and full
incoming-attack coverage. No row currently authorizes automatic flicking.

The recorder accepts ``--pid``, ``--record-keys``, ``--duration``, ``--enrage``,
``--output`` and ``--stop-file``. The 2026-11-14 read-only path uses the shared
NativeTelemetry serializer and synchronous C acquisition. It retains complete
schema-1 frames, all four native event queues and their loss counters, guarded
P2 phase/enrage observations, target/pose, effects, hazards, bars, inventory and
abilities. No queue is drained a second time by the prayer recorder. Exact
native nanoseconds and sequence are added without a display-time round trip.
Manual enrage stays a separate label and never replaces a native observation.

All four manual prayer-key edges are retained. Poll intervals are measured at
key edges, not assumed to match the requested 10 ms period. Complete down/up
transitions between polls may be missed; manual_actions_lost stays unknown.
No attack style or phase is labelled merely from an animation ID. Missing
phase-5 semantics stay unknown; use bounded manual annotations when needed.
The legacy automatic trial is still gated off by the shipped profile and is
separate from the read-only recording path. The new path constructs no trial,
input device, planner or controller, and always closes its native reader.

The same new local capture can be passed to the S0a replay and D8 shadow or
readiness commands, without reconstructing omitted queues. This does not make
the capture a clean shadow run: current coverage and watchdog failures remain.
Raw files stay local and may be much larger than the older reduced recordings;
use the finite duration (default 300 seconds) and a fresh ignored output file.

``work/analyze_telos_calibration.py`` supports either isolated
``--phase``/``--enrage`` labels or ``--annotations`` for mixed-phase captures,
plus ``--catalogue-output``. Annotation JSON has a ``sources`` array; each
entry contains capture_sha256, client_sha256, bounded intervals (original
session, start_ns, end_ns, phase, enrage, source and uncertainty_ns), and
optional labels keyed by sequence. Ambiguous/boundary cues stay unassigned.
Guide leads never become validated; cue-to-hit delays never become protection
deadlines. Raw stages are not decoded by the general analyzer.
Hit pairing is disabled by default; ``--isolated-melee`` enables descriptive
cue-to-hit observations only with an explicitly labelled phase-1 capture.
Summaries now expose all four native queue-loss totals, preserving unknown
counters, and retain true/false/unknown historical input provenance. An old
automatic capture is never reported as read-only merely because it is analyzed
offline. Output aliases of a capture, annotations or another output are rejected
before any write, including hard links.

``docs/validation/telos-prayer-calibration-2026-11-13.json`` records compact
provenance, counts, guard scope and missing coverage. Offline P2 annotations
use only the exact original-profile phase mapping and active-Telos guards in
P2's committed validation report, with 100 ms exclusions at phase boundaries.
