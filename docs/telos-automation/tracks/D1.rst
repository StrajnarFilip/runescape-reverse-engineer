D1 - Encounter tracker
======================

:Status: in progress
:Wave: 1
:Branch: ``telos/D1``
:Kind: Python

Shared rules and procedure: ``../README.rst``.

Goal
----

A state machine that turns the event stream into an encounter picture: current
phase, attack index within the cycle, the next expected attack, and the list of
pending incoming threats with their prayer-check windows.

Read first
----------

* ``python/rs3_reader/bot/world_state.py`` and ``replay.py`` from S0a.
* ``include/rs3/prayer.h``: ``rs3_prayer_threat`` and
  ``rs3_prayer_frame.coverage_until_ns``.
* ``docs/prayer-flick.rst``, sections "NPC action event stream" and "Planner
  contract".
* ``docs/telos-melee-research.rst``, section "Telos encounter model".
* ``profiles/telos_attacks.json`` once P6 has produced it.

Owns
----

* ``python/rs3_reader/bot/encounter_tracker.py``
* ``tests/python/test_bot_encounter_tracker.py``

Depends on
----------

S0a. Loads P6's attack table; until it exists, use only the four sequences in
``docs/validation/telos-prayer-calibration-2026-11-10.json``. Uses P2's phase
when present and otherwise reports phase as unknown.

Delivers
--------

``EncounterState``: phase, attack index, next attack and confidence, pending
threats in the shape ``rs3_prayer_threat`` needs, and ``coverage_until``. An
unknown sequence, an event-queue gap or a scene change drops coverage to
unknown instead of guessing.

Done when
---------

Replaying the two existing 300% phase 1 captures yields a threat before every
labelled damaging attack, no threat is fabricated from an unlabelled sequence,
and gap and scene-change cases are covered by tests.

Needs the user
--------------

Nothing. The two local captures under ``work/prayer_research/`` are the input.

Implementation and verification (2026-11-13)
------------------------------------------

``EncounterTracker.step(WorldState)`` returns immutable ``EncounterState``.
It keeps original event/session timestamps, deduplicates exact repeated drains,
checks age and scene identity, and invalidates accumulated state after queue
loss, unknown loss counts, sequence reuse/gaps, clock regression, ambiguous
Telos actors or bounded-queue overflow. Reapplications with new native event
IDs remain separate cues even when the animation ID repeats.

``AttackTable`` loads P6 JSON without importing native bindings. Lookup is
exact for executable hash, phase, enrage and context; overlapping rows remain
unknown. A missing file uses only the four historical original-profile labels,
restricted to 300% phase 1 and explicit ``isolated_p1_melee`` context. Runtime
phase stays unknown without a fresh P2 field; packed stage is not decoded.

Every labelled cue emits an ``IncomingThreat``. Unmeasured protection windows
and prayers stay null with flags=0; ``prayer_record()`` returns None so these
cannot enter the native planner as calibrated threats. The two local capture
replays produce 15 and 16 unresolved labelled threats, respectively, and none
from unlabelled sequences. Their offline phase/enrage annotations come from
the committed calibration report, not runtime inference. Measured sample end
time supplies replay age; missing capture age is not silently declared fresh.

Golden S0a no-input log SHA-256 digests for those captures are asserted in
``tests/python/test_bot_encounter_tracker.py``. Raw capture SHA-256 digests
are checked first. No gameplay rows or logs are committed. The 15 tracker
tests include synthetic calibrated-window and multi-hit rejection cases;
real captures do not acquire validated timing from those fixtures.
The Windows x64 Release build and all 10 CTest suites passed, with 93 Python
tests. P6's 28-row production catalogue also loads without native imports.

``observed_auto_count`` counts labelled cues since reset, not cycle position.
``attack_index``/``next_attack`` require an explicit measured non-auto cycle
anchor in P6; they remain unknown for current data. Coverage is always unknown
until complete incoming-attack prediction is calibrated. No four-tick cadence
or cue-to-hit delay is promoted into a protection deadline or safe idle gap.
``create_stack()`` exposes an observe-only S0a replay adapter that emits no
intents. Decision producers may consume its state after each step.

Requests
--------

* L follow-up, 2026-11-14: only promote a timing-calibrated cue when its current
  native NPC target is the exact observed local player. Unknown, clear, foreign
  or stale target evidence must leave it unresolved. The P1 entity reference
  alone is not an attack declaration; still require the calibrated attack row.
  Keep historical label/cycle observations separate from usable threat flags.

* P6: supply measured per-component protection windows and complete incoming
  coverage, including golems/projectiles. Current labelled threats are useful
  observations, not authorization to flick. Multi-hit rows without separately
  modelled component windows remain unresolved.
* P6: cycle anchors need ``cycle.validated``, native-labelled evidence,
  ``index_after`` and optional ``next_sequence`` on a confirmed non-auto cue.
  Do not infer seven/three-auto positions, phase carry or special skips from
  a guide or elapsed time. Current P6 rows do not supply these anchors.
* P2/L: provide fresh mapped phase/enrage fields and preserve client digest.
  Raw stage alone is not phase. Explicit isolated-melee context requires
  observed/calibrated encounter conditions, not just the player's chosen style.
* D2/L: only ``prayer_record()`` output may be translated to native threats;
  None windows and ``coverage_until_ns=None`` must block Soul Split planning.
  A calibrated single threat does not establish complete coverage. D3 needs
  independently measured damage bounds and defensive eligibility before timed
  survival proposals; current real threats deliberately omit those fields.
