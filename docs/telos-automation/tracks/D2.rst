Goal
----

Drive the existing C prayer planner from live encounter state: feed D1's
threats to ``rs3_prayer_step``, turn a SET decision into a prayer intent, report
accepted input with ``rs3_prayer_note_sent``, and wait for the observed
overhead.

Depends on
----------

D1 (threats), P6 (validated windows), A1 (actuator).

Delivers
--------

Prayer intents at the second-highest priority, with the planner's reason
attached as evidence. The ``attack_coverage_validated`` and
``prayer_check_deadline_validated`` flags are set per phase and enrage band,
and only for bands where P6 marks the windows validated. Everywhere else the
executor stays in protection and proposes no Soul Split window.

Done when
---------

Replay tests show protection is up inside every validated check window of the
captures, a planner FAULT stops proposals until reset, and no proposal is made
for an unvalidated band.

Needs the user
--------------

Nothing in this track. Live use starts at rung 2 of track L.

Offline implementation (2026-11-13)
-----------------------------------

``PrayerExecutor`` adapts D1/P6 state to the existing C planner; it does not
reimplement timing. Import/construction opens no DLL. ``NativePrayerPlanner``
loads the existing ABI lazily only for a calibrated band or explicit test.
No method sends a key. D6 must call note_sent only after actual input acceptance.

Validation is derived per exact phase/enrage/client/context from P6 native
samples, measured windows and coverage. Profile booleans and guide labels
cannot upgrade unvalidated P6 rows. Non-empty measured attack data is required;
empty bands are not vacuously valid. Unknown phase, stale encounter state,
unresolved threats, changed windows or wrong protection reject proposals.
Coverage remains independent: measured protection may be proposed without a
Soul Split gap; Soul Split requires explicit complete P6 and D1 coverage.

Intents carry planner reasons and the configured Ctrl+F1/F2/F3/F4 binding.
The four chords are preserved. P5 struct IDs were added from its decoder;
when live bar data is available, changed/unmapped keys block the old profile
binding. can_send re-runs the C planner and binding checks before dispatch.
Only newer overhead feedback acknowledges accepted input. Planner FAULT and
scene/build changes latch until explicit reset after re-observation.

Twelve D2 tests pass, including the actual C planner's protect/WAIT_ACK/observed
Melee/return-to-Soul-Split sequence on synthetic measured windows. This does
not calibrate a real server deadline. A real-capture golden replay emits no
toggle. All 10 CTest suites pass in the Windows x64 Release build (90 Python
tests). Current global flags and every real P6 band remain unvalidated.
